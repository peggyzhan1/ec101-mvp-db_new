先按这套表下载。费用平台「下载核验报告」走同一列：活动一份、券一份。业务文件只有前三张表，不含「字段说明」。

## 报告怎么切

一份报告 = **一个活动 × 一次核算**。不是整批导入、也不是全店所有订单。

| 工作表 | 一行是什么 | 要不要 |
|---|---|---|
| 活动核验结论 | 整份报告的封面汇总 | 要 |
| 参与订单明细 | 参加了这个活动的一张订单 | **主表，请先评这些字段** |
| 订单商品行（附录） | 上面某张订单的一个商品行 | 建议保留作抽查，默认不拿来加总费用 |
| 字段说明 | 给评审用 | 开发时不会导出给业务 |

没有活动核销的订单不会出现。

## 参与订单明细：建议字段

从**订单**看：订单明细的优惠金额只作备查。关联了活动就填活动优惠金额（满赠则以后填满赠数量）；关联了券就填优惠券优惠金额。没有关联的列留空。计费仍只认活动核销、券核销。

| 字段 | 现在能否填 | 作用 |
|---|---|---|
| 序号 | 能 | 行号 |
| 经销商名称 / 平台名称 | 能 | 这份报告属于谁 |
| 活动编号 / 活动名称 / 活动类型 | 能 | 哪个活动 |
| 核算日 / 释放截止时刻 | 能 | 这次怎么判 T-2 |
| 单据编号 | 能 | 订单主键 |
| 下单时间 | 能 | 是否早于截止时刻 |
| 客户编号 / 客户名称 / 所属业务员 | 能 | 对账找人 |
| 订单状态 | 能 | 是否「已完成」 |
| 订单来源 / 订单类型 / 支付方式 | 能 | 备查，不参与释放 |
| 活动商品金额 | 能 | 该单在本活动核销里的商品金额 |
| 订单优惠金额（备查） | 能 | 订单明细优惠加总，只对照 |
| **活动优惠金额** | 能 | 关联活动才有值；满减计费用这一列 |
| 优惠券优惠金额 | 能 | 关联券才有值，否则空 |
| 满赠数量 | 现在空 | 关联满赠才有值；配置进表后再填 |
| 是否可释放 / 释放结论 | 能 | 是 / 否，以及原因 |
| 理论权益 / 一致性 / 差异金额 | 有规则时可填 | 满减验收表：理论 2040、一致 136/136 |

商品行仍放附录，给抽查用，不加总当费用。

## 封面汇总（现在能出的数）

样例：可口可乐满减，参与 136，可释放 133，待释放 3，核销 2040，可释放金额 1995，待释放 45。有规则后理论权益 2040、一致 136/136。

## 已按这套表落地

1. 附录「订单商品行」随报告一起下载，只抽查，不加总当费用。
2. 优惠券另出一份按券的报告；满减报告订单上仍出现「优惠券优惠金额」。
3. 同一张单叠了满减 15 + 券 200：券报告里「活动优惠金额」保持空。
4. 理论 / 一致性现在填写。满减封面理论 2040、一致 136/136；券封面理论 200、一致 1/1。

费用平台「活动中心 / 权益核算 / 核销与对账 / 数据接入」点「下载核验报告」：

- 活动：`GET /api/fee-tpm/activities/{id}/verification-report?calc_batch_id=`
- 券：`GET /api/fee-tpm/coupons/{id}/verification-report?calc_batch_id=`
