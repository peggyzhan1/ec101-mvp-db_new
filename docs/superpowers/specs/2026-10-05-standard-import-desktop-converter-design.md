# EC101 标准数据导入与 Windows 转换工具设计

## 目标

取消数据库中的 RAW 和 STANDARD 物理分层。快马、舟谱等平台的原始导出文件先由本地 Windows 转换工具转换为统一的标准 Excel；费用平台只接收该标准文件，原子写入业务事实并自动生成核算结果。

原始文件仍须保留为可审计证据，但不以逐行原始字段写入数据库。

## 已确认约束

- 首期平台：快马、舟谱。
- 转换器以 Windows 桌面工具交付，内部复用 Python 转换逻辑；不要求业务人员运行脚本或安装 Python。
- 费用平台只上传转换后的标准 Excel，不上传或解析平台原始文件。
- 标准 Excel 是固定完整模板；无数据工作表仍必须保留表头。
- 覆盖客户、商品、订单、订单明细、活动、活动规则、活动权益、活动范围、订单活动、履约和优惠券；不引入 TPM。
- 每次导入是某一经销商、平台和覆盖期间的全量快照。同范围重导创建新版本并替换当前生效版本。
- 任意阻断性校验失败时整包不入库；成功时导入和当前版本切换必须在单一事务中完成。
- 导入成功后自动核算满减、满赠和优惠券，输出权益核对、放行候选、活动费用汇总和质量问题。
- 首期沿用 SQLite、Python API 和现有 React 费用平台。
- 原始文件及标准快照保存到受控文件目录；数据库只保存元数据、相对路径、SHA-256、大小和所属导入版本。
- 从新数据库重新导入真实试点数据，不迁移现有四层结构或旧主键。

## 总体架构

```text
快马/舟谱原始导出
       │
       ▼
Windows 数据转换工具
  ├─ 平台适配器（快马 / 舟谱）
  ├─ 共享标准模型与校验器
  └─ 标准 Excel
       │
       ▼
费用平台上传 API
  ├─ 模板与业务规则校验
  ├─ 文件归档
  ├─ 当前快照原子替换
  └─ 自动核算
       │
       ▼
SQLite 业务事实与核算输出
```

转换器和平台导入器共享标准模型定义，但职责严格分离：转换器理解原始平台列和文件组合；导入器只理解标准 Excel。

## 标准 Excel 契约

工作簿必须包含：

1. `导入清单`
2. `客户`
3. `商品`
4. `订单`
5. `订单明细`
6. `活动`
7. `活动规则`
8. `活动权益`
9. `活动范围`
10. `订单活动`
11. `履约`
12. `优惠券`

`导入清单`至少保存模板版本、转换器版本、经销商编码和名称、平台、覆盖起止日期、生成时间、各工作表记录数。所有业务标识（订单号、客户号、商品号、活动导入键、券号）均以文本读取，禁止 Excel 自动转为科学计数法。

跨表关联使用稳定的业务键，不使用导入后的 SQLite 自增主键。标准模型的活动是费用归集的最高业务对象；不包含 TPM、预算申请或 TPM 编号。

## 新数据库模型

数据库按用途组织，不再称为或依赖四层模型。

### 导入审计

- `import_batch`：经销商、平台、期间、版本、状态、当前版本标记、导入及核算时间。
- `import_file`：原始文件与标准文件的角色、相对路径、文件名、SHA-256、大小、归档时间。
- `import_validation_issue`：导入前校验错误及警告，包含工作表、行号、字段、错误码和说明。

这些表保存导入过程的证据和版本，不保存原始平台字段行。

### 业务事实

保留并重建经销商平台、客户、商品、订单、订单明细、活动、活动规则、活动权益、活动范围、订单活动、履约和优惠券。每个业务事实都关联 `import_batch_id`，以便当前版本切换和历史重放；查询 API 默认只返回当前生效批次的数据。

### 核算输出

- `calculation_run`
- `entitlement_check`
- `release_candidate`
- `activity_fee_summary`
- `calculation_quality_issue`

输出关联 `import_batch_id` 与 `calculation_run_id`。费用以活动为维度汇总，满减、满赠、优惠券共用同一核算入口；不含 TPM 外键或字段。

## 版本与导入流程

1. 业务人员从快马或舟谱下载源文件。
2. 在 Windows 工具中选择平台、经销商和所需源文件。
3. 工具执行平台专属解析、共享标准校验，生成标准 Excel 和仅用于归档的 `sources.zip`；失败时只在本地给出错误报告。
4. 业务人员在费用平台上传标准 Excel 及其同次生成的 `sources.zip`。平台只校验归档包的文件清单和哈希，不解析其中的原始平台字段。
5. API 校验工作表、模板版本、数据类型、主外键、重复键、覆盖范围和三类促销的核算前置条件。
6. 校验失败：创建失败审计记录和错误报告，不写业务事实。
7. 校验成功：归档标准文件，登记输入原始文件清单及其哈希，在单一事务中写入新版本业务事实、停用旧当前版本并激活新版本。
8. 事务提交后自动运行核算并记录核算输出；核算失败时批次保留为已导入但核算失败，不能被视为已完成。

原始文件由转换工具打包为 `sources.zip` 并随标准 Excel 作为归档附件提交；费用平台不从中读取业务字段。

## Windows 桌面转换工具

工具以单个 Windows 可执行文件交付，使用图形界面完成：

- 选择快马或舟谱；
- 选择经销商；
- 按平台要求选择订单、活动、客户、商品及其他源文件；
- 显示文件缺失、列缺失、期间不一致和关键关联失败；
- 生成标准 Excel、转换报告及可选的原始文件归档包；
- 显示模板与转换器版本。

代码结构为 `converters/common`（标准模型、工作簿读写、校验）、`converters/kuaima` 和 `converters/zhoupu`（各自的源文件适配器）、`desktop_converter`（Windows GUI 与打包入口）。新增平台只实现适配器，不修改标准模板和费用平台导入逻辑。

## 费用平台改造

新增“数据导入”工作区，提供文件选择、上传进度、校验结果、错误报告下载、导入历史、当前版本、覆盖期间及核算状态。原有业务数据和费用页面继续通过 API 查询当前版本事实及对应核算输出。

新增 API 至少包括：

- `POST /imports`：上传标准 Excel 与归档附件。
- `GET /imports`：导入历史和状态。
- `GET /imports/{id}`：详情、校验错误、文件和核算状态。
- `GET /imports/{id}/issues`：错误报告。

## 验证

端到端测试必须覆盖：

1. 快马真实样本：原始文件转换为标准 Excel、上传、全量校验、导入和自动核算。
2. 舟谱真实样本：覆盖 SXD/XD 履约及平台特例后走同一标准导入链路。
3. 缺少工作表、列名错误、跨表孤儿记录、重复业务键、日期/金额格式错误均整包阻断。
4. 同范围重导只保留一个当前版本，旧版本文件和业务事实可追溯。
5. 满减、满赠、优惠券均生成四类核算输出，且费用不含 TPM。
6. 归档文件的哈希与登记元数据一致。

## 非目标

- 不实现多用户权限、线上部署或 MySQL/PostgreSQL 迁移。
- 不在费用平台直接解析快马或舟谱原始列。
- 不迁移旧 SQLite 表或主键。
- 不接入 TPM、预算申请、支付或 ERP 上账。
