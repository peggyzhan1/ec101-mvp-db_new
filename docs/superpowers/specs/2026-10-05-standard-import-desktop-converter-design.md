# EC101 标准数据导入与 Windows 转换工具设计

## 目标

不同平台的原始导出文件先由 Windows 桌面转换工具转换成固定的 EC101 标准 Excel。费用平台只导入标准 Excel；数据库不再保留 RAW、STANDARD、CORE、RESULT 四层物理分层，而是保存导入审计、业务事实和核算输出。

原始平台文件和标准 Excel 仍以文件归档形式保留，便于审计和重转换；数据库不保存原始平台字段的逐行 RAW 表。

## 已确认边界

- 首期转换器：快马、舟谱。
- 首期交付：Windows 桌面工具；业务人员不运行 Python 脚本。
- 工具支持选择平台、经销商、源文件，并在本地录入活动配置。
- 工具生成固定完整标准 Excel 和 `sources.zip`；费用平台上传两者，但只解析标准 Excel，原始包只做归档。
- 标准 Excel 字段以当前舟谱 `std_field_mapping`/EC101 标准字段为基线，并按已审核的数据字典冻结；不增加动态扩展属性表。
- 首期不包含 TPM 和标准销售明细；费用核算使用订单明细、活动核销、优惠券核销和履约事实。
- 每次导入是经销商+平台+覆盖期间的全量快照；同范围重导生成新版本并切换当前版本。
- 校验失败整包不写入；成功导入后自动核算。
- 首期继续使用 SQLite、Python API 和 React 费用平台。

## 标准 Excel 固定工作表与字段

空数据表也必须保留表头。编号、单号、券号均按文本处理，禁止 Excel 科学计数法。

### 导入清单

`模板版本`、`转换工具版本`、`经销商名称`、`平台名称`、`数据开始日期`、`数据结束日期`、`生成时间`。

### 标准客户

`客户编号`、`客户名称`、`客户类型`、`客户区域`、`详细地址`、`联系电话`、`添加时间`、`所属业务员`。

### 标准商品

`商品编号`、`商品名称`、`商品品牌`、`商品目录`、`商品条码`、`商品规格`、`基本单位`、`箱规`、`每箱基本单位数量`。

### 标准订单明细

`单据编号`、`下单时间`、`客户编号`、`客户名称`、`商品编号`、`商品名称`、`商品目录`、`规格`、`商品条码`、`单位`、`数量`、`优惠前金额`、`活动编号`、`优惠券编号`、`优惠金额`、`实付金额`、`业务员`、`订单来源`、`订单类型`、`订单状态`、`支付方式`、`下游订单编号`、`单价`、`退货数量`。

订单明细中的`活动编号`和`优惠券编号`是前端展示字段；多个编号以分号拼接，核算分别使用活动核销明细和优惠券核销明细。

### 满减/满赠活动配置

活动域固定为四张表，优惠券不属于活动域。

#### 标准活动

`活动编号`、`活动名称`、`活动类型`、`促销方式`、`开始时间`、`结束时间`、`是否允许叠加活动`、`是否允许叠加优惠券`、`活动状态`。

#### 标准活动规则

`活动编号`、`规则编号`、`门槛类型`、`门槛值`、`立减金额`、`是否免邮`。

#### 标准活动权益

`活动编号`、`规则编号`、`权益编号`、`权益类型`、`赠品商品编号`、`赠品商品名称`、`赠品数量`、`赠品单位`。

权益类型首期为立减、赠品、免邮；优惠券不放入活动权益。

#### 标准活动范围

`活动编号`、`范围编号`、`范围类别`、`范围维度`、`范围值`。

### 标准活动核销明细

一订单参与多个活动时一活动一行：

`活动编号`、`活动名称`、`客户编号`、`客户`、`所属业务员`、`订单号`、`商品总金额`、`优惠金额`。

### 优惠券配置域

优惠券与满减/满赠活动完全独立，不使用活动编号，不建立活动外键。优惠券通过订单与活动间接汇合。

#### 标准优惠券配置

`优惠券配置编号`、`优惠券名称`、`券类型`、`配置状态`。

#### 标准优惠券发放规则

`优惠券配置编号`、`发放方式`、`发放开始时间`、`发放结束时间`、`自动发放时间`、`每次发放数量`、`每客户领取上限`、`每日领取上限`、`规则状态`。

#### 标准优惠券使用规则

`优惠券配置编号`、`券类型`、`有效期类型`、`使用开始时间`、`使用结束时间`、`领取后有效天数`、`每张券最多使用次数`、`规则状态`。

#### 标准优惠券适用范围

`优惠券配置编号`、`范围编号`、`范围类别`、`范围维度`、`范围值`。

#### 标准优惠券核销明细

一张券一行：

`优惠券编号`、`客户编号`、`客户`、`所属业务员`、`领取时间`、`使用期限`、`状态`、`使用时间`、`订单号`、`优惠金额`。

### 标准履约

`单据编号`、`下游订单编号`、`履约订单状态`、`出库时间`、`完成时间`、`结款状态`、`退货数量`。

标准履约适用于所有平台；快马没有下游订单时，`下游订单编号`为空。`T-2 是否可放行`属于核算输出，不进入标准数据。

## 核心关系

活动和优惠券通过订单间接关联，不直接互相关联：

```text
订单
├─ 订单活动执行 / 活动核销明细 ──> 满减/满赠活动
└─ 券核销记录 / 优惠券核销明细 ──> 优惠券
```

同一订单可以同时有活动核销和券核销。RESULT 先分别计算活动优惠与券优惠，再按订单汇总，避免重复计算。

## Windows 转换工具

工具内部复用现有 `std_mapping.py` 的标准字段语义和平台映射，但将 `std_field_mapping` 从数据库迁移为版本化配置文件。平台适配器负责把快马/舟谱源列转换为上述标准列；共用模板校验器负责字段、日期、金额和跨表键检查。

工具界面包括：平台选择、经销商选择、源文件选择、活动配置录入、优惠券配置录入、转换预览、错误报告、标准 Excel 与 `sources.zip` 生成。

活动配置录入页生成活动四张表；优惠券配置录入页生成优惠券配置、发放规则、使用规则和适用范围四张表。两种录入页完全分开。

## 数据库与导入流程

数据库保存三类实体：

1. 导入审计：导入批次、版本、文件角色、相对路径、哈希、大小、校验问题和状态。
2. 业务事实：按标准数据落地并由 CORE 关系整合的客户、商品、订单、活动、活动核销、履约、优惠券配置和优惠券核销事实。
3. 核算输出：核算批次、权益核对、放行候选、活动费用汇总、质量问题。

导入顺序：上传标准 Excel 和 `sources.zip` → 校验模板和业务键 → 失败则零写入 → 成功则归档文件并原子切换当前快照 → 自动核算。查询 API 默认只返回当前快照。

## 验证范围

- 快马、舟谱真实样本均能转换为同一标准 Excel。
- 标准客户、商品、订单明细、活动四表、活动核销、优惠券四表、优惠券核销和履约均能通过导入。
- 重复键、孤儿订单/客户/商品、错误日期金额、活动或优惠券配置缺失均整包阻断。
- 同一订单同时存在活动核销与券核销时，RESULT 分开计算并正确汇总。
- 原始文件归档包哈希与导入清单一致。

## 非目标

- 不迁移现有旧 SQLite 数据或旧主键。
- 不在费用平台解析快马/舟谱原始文件。
- 不引入 TPM、标准销售明细、支付或 ERP 上账。
- 不保留 RAW/STANDARD 逐行数据库表。
