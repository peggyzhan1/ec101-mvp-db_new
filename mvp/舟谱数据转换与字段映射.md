# 舟谱数据转换与字段映射

费用平台里已导入的舟谱-羿柏工作簿，由 `converters/zhoupu_snapshot.py` 的 `convert_zhoupu_snapshot` 生成。转换器版本号是 `zhoupu-snapshot-v1`。它把销售订单（SXD）和履约单（XD）合成标准订单，再配上满赠活动和返券台账。

桌面转换工具当前调用的是 `converters/zhoupu.py` 的 `convert_zhoupu`。那条路径按列直译，不做客户复合键、XD 状态回写、无 SXD 的履约建单和券面额解析。对照见文末。

入库和核算不在转换器里。工作簿上传后由 `mvp/import_service.py` 写入 `mvp/ec101_standard.db`，再由 `mvp/actual_result_calculator.py` 计算。表结构见 [`EC101_标准库数据字典.md`](EC101_标准库数据字典.md)，核算公式见 [`实际发生核算逻辑.md`](实际发生核算逻辑.md)。

试点经销商是「羿柏」，平台名称是「舟谱」。覆盖日期写死为 2026-08-19 到 2026-09-08。客户、商品、SXD、XD 的表头都在第 4 行；优惠券台账的表头在第 3 行。

## 1. 处理顺序

1. 读客户档案。客户编号用「客户名称|助记码」。整份档案先进入「标准客户」。
2. 读商品档案。商品编号用「商品唯一序号」。整份档案先进入「标准商品」。
3. 把两份 XD 文件编成索引：每张履约单的状态、签收时间、出库时间、结款、退货，以及条码、名称到商品编号的对照。
4. 按文件列表读 SXD。只保留订单编号以 `SXD` 开头的行。同一订单只采用最先出现的那份文件，后面文件里的同一订单整单丢弃。同一文件内的行先保留，再按商品编号合并数量和金额。
5. SXD 若能在 XD 索引里找到下游单号，订单状态改用 XD 的汇总状态，并写一行「标准履约」。找不到下游单时，不写履约。
6. XD 里尚未被任何 SXD 引用、且单据号以 `XD` 开头的履约单，单独建成订单，订单来源写「XD履约(无SXD)」。
7. 读优惠券台账，写入「标准优惠券核销明细」。能唯一对上订单号的才填写订单号。
8. 写入满赠活动 ZP-MZ-001 和返券配置 ZP-FQ-CFG。「标准活动核销明细」保持为空。

商品编号、条码、商品 id 若是 `123.0` 这种形式，先去掉末尾的 `.0`。

## 3. 客户

同一「客户名称|助记码」只保留第一次出现的行。助记码先取「助记码」，没有再取「客户助记码」。

| 标准客户 | 舟谱源列 |
|---|---|
| 客户编号 | 客户名称 \| 助记码 |
| 客户名称 | 客户名称 |
| 客户类型 | （空） |
| 客户区域 | 片区 |
| 详细地址 | 客户地址 |
| 联系电话 | 老板电话 |
| 添加时间 | （空） |
| 所属业务员 | 专属员工 |

订单对客户时按下面顺序找编号：

1. XD 上的「客户名称|客户助记码」能对上档案。
2. SXD 订单上的客户名称，配上 XD 的助记码，能对上档案。
3. 只用客户名称，并且这个名称在档案里只对应一个复合编号。先试订单上的名称，再试 XD 上的名称。
4. 都对不上时，客户编号写成 `UNRESOLVED:` 加订单号，并补一条只有编号和名称的客户。

没有 SXD 的 XD 单据，先试「客户名称|客户助记码」。对不上则编号为 `UNRESOLVED:` 加单据号。客户名称等于「测试」的单据整单不建。

## 4. 商品

同一商品唯一序号只保留第一次。同一条码只保留第一次看到的商品编号，供后面按条码回找。

| 标准商品 | 舟谱源列 | 说明 |
|---|---|---|
| 商品编号 | 商品唯一序号 | 去掉末尾 `.0` |
| 商品名称 | 商品名称 | |
| 商品品牌 | 品牌 | |
| 商品目录 | 类别 | |
| 商品条码 | 小单位条码 | 去掉末尾 `.0` |
| 商品规格 | （空） | |
| 基本单位 | （空） | |
| 箱规 | 单位换算 | 原文 |
| 每箱基本单位数量 | 大单位换算，没有则用单位换算 | 见下 |

每箱数量的取法：文本本身是正数就用它；否则在 `N*M`、`N×M`、`NxM` 里取后一个数；再否则取文本里第一个正数。两个字段都解析不到则为空。

SXD 商品行对编号的顺序：

1. 下游 XD 上，同一单据、同一条码已经对应到档案里的商品 id。
2. 下游 XD 上，同一单据、同一商品名称已经对应到档案里的商品 id。
3. 商品档案的小单位条码能对上这一行的条码。
4. 对不上时，商品编号写成 `UNMATCHED:` 加上条码、商品名称、源商品编号或行序号中第一个有值的内容，并补一条商品。商品名称仍用订单上的原文。

没有 SXD 的 XD 行：源列「商品id」能在档案里找到就用档案名称和条码；找不到则编号为 `UNMATCHED:` 加上商品名称或商品 id。

赠品在一部分 SXD 上对不到档案，商品编号会变成 `UNMATCHED:(赠品)雪碧抱枕`，商品名称仍是 `(赠品)雪碧抱枕`。核算按名称计数时，这个编号前缀不影响命中。

## 5. SXD 订单

只收订单编号以 `SXD` 开头的行。文件按列表顺序读。某个订单号第一次出现在哪份文件，就只用那份文件里的行；后面文件里的同号订单整单不进入。

同一订单、同一商品编号的多行要合并：数量、优惠前金额、实际金额、优惠金额分别相加。单价留第一行的实际单价。类目、单位留第一行。

数量取「实际数量」，没有则「订单数量（大）」，再没有则「订单数量」。优惠金额由转换器计算：优惠前金额和实际金额都有值时，优惠金额 = 优惠前金额 − 实际金额。这一列会进订单行，当前核算不把它当成满减。

下单时间只有日期时补 `00:00:00`。源时间为空时写成 `1900-01-01 00:00:00`。

订单状态：下游单号能在 XD 索引里找到时，用该 XD 全部行汇总出的状态；找不到时用这条 SXD 自己的「订单状态」；仍为空则写「未知」。

XD 多行状态的汇总规则：

- 每一行都是「已完成」，结果是「已完成」。
- 出现不在下列名单里的状态时，取第一个这种状态。
- 否则取得分最低的那个：待审核 0、待出库 1、待入库 2、待签收 3、已完成 4。混有未完成状态时，保留进度更早的状态。

| 标准订单明细 | SXD 来源 |
|---|---|
| 单据编号 | 订单编号 |
| 下单时间 | 下单时间 |
| 客户编号 / 客户名称 | 上一节的匹配结果 |
| 商品编号 / 商品名称 / 商品条码 | 上一节的匹配结果；对上档案时名称和条码优先用档案 |
| 商品目录 | 类目 |
| 规格 | （空） |
| 单位 | 单位名称，没有则单位名称（大） |
| 数量 | 实际数量 / 订单数量（大） / 订单数量，同商品相加 |
| 优惠前金额 | 优惠前金额，同商品相加 |
| 活动编号 / 优惠券编号 | （空） |
| 优惠金额 | 优惠前金额 − 实际金额，同商品相加 |
| 实付金额 | 实际金额，同商品相加 |
| 业务员 / 订单类型 / 支付方式 / 退货数量 | （空） |
| 订单来源 | （空） |
| 订单状态 | XD 汇总状态，或 SXD 订单状态，或「未知」 |
| 下游订单编号 | 下游订单编号 |
| 单价 | 第一行的实际单价 |

能找到 XD 时另写一行履约：

| 标准履约 | 来源 |
|---|---|
| 单据编号 | SXD 订单编号 |
| 下游订单编号 | SXD 的下游订单编号 |
| 履约订单状态 | XD 汇总状态，空则「未知」 |
| 出库时间 | XD「出(入)库时间」的最大值 |
| 完成时间 | 有签收时间则取最大签收时间，否则取最大出库时间 |
| 结款状态 | XD 结款状态 |
| 退货数量 | XD 文件含「退货结算数量」时，各行相加；没有该列则空 |

SXD 上写了下游单号、但这张 XD 不在已加载的 XD 文件里时，不写履约，订单状态保持 SXD 原文。满赠里有 11 张这样的 SXD，状态是「已下发」，赠品行名称是 `(赠品)雪碧抱枕`。当前核算按订单行名称计数，这 11 行仍算进实发。说明见核算文档。

## 6. 只有 XD、没有 SXD 的订单

同时满足下面几条才建单：

- 单据号以 `XD` 开头。
- 单据号不以 `TD` 开头。
- 没有任何 SXD 的下游订单编号指向它。
- 客户名称不是「测试」。
- 这张单据还没有处理过。

| 标准订单明细 | XD 来源 |
|---|---|
| 单据编号 | 单据 |
| 下单时间 | 单据时间；没有则用完成时间；再没有则 `1900-01-01 00:00:00` |
| 客户编号 / 客户名称 | 客户名称\|客户助记码，或 `UNRESOLVED:` 加单据号 |
| 商品编号 | 商品id，且该编号在档案中；否则 `UNMATCHED:` 加名称或 id |
| 商品名称 | 档案名称，或 XD 商品名称 |
| 规格 | 规格 |
| 商品条码 | 对上档案时用档案条码，否则用 XD 条形码 |
| 数量 | 按顺序取到的第一个有值列：下单数量、下单数量（小）、下单数量(小)、下单数量（中）、下单数量（大）。同商品相加 |
| 优惠前金额 / 实付金额 | 下单金额，同商品相加 |
| 优惠金额 | 0 |
| 订单来源 | `XD履约(无SXD)` |
| 订单状态 | 该单据各行按上一节规则汇总，空则「未知」 |
| 下游订单编号 | （空） |
| 单价 | （空） |

这类订单都会写履约。单据编号就是 XD 单号，下游订单编号为空，退货数量为空。完成时间同样是最大签收时间，否则最大出库时间。

## 7. 优惠券台账

表头在第 3 行。券名为空的行跳过。券编号是 `ZP-FQ-` 加四位行号，行号从 0 起，按文件中的数据行位置编号；空券名的行虽然跳过，位置号仍然占用。

| 标准优惠券核销明细 | 来源 | 说明 |
|---|---|---|
| 优惠券编号 | `ZP-FQ-` + 行号 | |
| 客户编号 | 领取客户 | 这个名称在客户档案里只对应一个复合编号时，改写成复合编号；否则原样保留领取客户文本 |
| 客户 | 领取客户 | |
| 所属业务员 / 领取时间 / 使用时间 | （空） | |
| 状态 | 已使用张数 | 大于 0 为「已使用」，否则「已领取」 |
| 优惠金额 | 券名 | 仅已使用，且券名能匹配「返N元」时写入 N；已领取写空 |
| 订单号 | 关联单据编号 | 文本里没有逗号，并且这个单号已经在标准订单里，才写入 |
| 使用期限 | 关联单据编号 | 订单号没写上、但关联单据原文不是空时，写成 `关联单据:` 加原文 |

关联单据里含逗号的，订单号留空，使用期限保留原文。核算把这种记录看成已经使用、但不能归到唯一订单。试点有 3 张，每张 15 元。领取客户对不上档案的，客户编号就是原始名称，入库后会记「券领取客户未匹配」。试点中的例子是「洋洋百货」。

「标准活动核销明细」没有行。满赠是否发生，由核算器按赠品名称在活动时间内清点订单行。

## 9. 桌面工具的直译转换

`convert_zhoupu` 表头同样在第 4 行，适合字段已经接近标准表、且不需要把 SXD 与 XD 合成的文件。已导入的羿柏试点工作簿不来自这个函数。

| 标准列 | 桌面转换读取的源列 |
|---|---|
| 客户编号 | 客户唯一序号，或客户编码 |
| 客户区域 / 详细地址 / 联系电话 / 所属业务员 | 片区 / 客户地址 / 老板电话 / 专属员工 |
| 商品编号 | 商品唯一序号，或商品编号，或商品id |
| 商品条码 / 商品目录 / 箱规 / 每箱基本单位数量 | 小单位条码或条形码 / 类别 / 单位换算 / 大单位换算 |
| 订单客户编号 | 客户编码 |
| 数量 | 实际数量，或订单数量（大），或订单数量 |
| 实付金额 / 单价 / 订单状态 / 下游订单编号 | 实际金额 / 实际单价 / 订单状态 / 下游订单编号 |
