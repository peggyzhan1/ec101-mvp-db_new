# 快马数据转换与字段映射

快马源文件由 `converters/kuaima.py` 的 `convert_kuaima` 转成 15 张工作表的 `standard.xlsx`。兴路强试点的文件清单、活动编号、赠品和券配置写在 `converters/kuaima_snapshot.py`。桌面转换工具选「快马」时调用的也是 `convert_kuaima`。

转换只产出工作簿。入库和核算在后面：`mvp/import_service.py` 把工作表写入 `mvp/ec101_standard.db`，`mvp/actual_result_calculator.py` 再按库里的字段出结果。字段进库后的含义见 [`EC101_标准库数据字典.md`](EC101_标准库数据字典.md)，核算公式见 [`实际发生核算逻辑.md`](实际发生核算逻辑.md)。

试点经销商是「深圳市兴路强商贸有限公司」，平台名称是「快马」。覆盖日期是 2026-08-19 到 2026-09-17。

## 1. 处理顺序

1. 读客户档案，写入「标准客户」。客户编号为空的行丢掉。
2. 读商品档案，写入「标准商品」。商品编号为空的行丢掉。
3. 按给定顺序读订单明细。同一订单号若已在更早的文件里出现过，后面文件里的该订单整单跳过；同一文件里的多行全部保留。
4. 订单里出现、商品档案里没有的商品编号，补一条商品。品牌、箱规、每箱数量留空，名称、目录、条码、规格、单位沿用订单行。
5. 订单里出现、客户档案里没有的客户编号，补一条客户。只填客户编号、客户名称、所属业务员。
6. 读活动核销文件。按活动编号加订单号汇总优惠金额，写入「标准活动核销明细」。核销里的订单号必须已经在订单里，否则该行跳过。
7. 把命中的活动编号写回订单行的「活动编号」。一单参加多个活动时用「、」连接。
8. 读优惠券领用明细，写入「标准优惠券核销明细」。券上的客户若还不在客户表里，同样补一条客户。
9. 每张订单补一行「标准履约」。履约状态抄订单状态，出库时间、完成时间、下游单号、结款状态、退货数量都留空。
10. 把调用方传入的活动、规则、权益、范围，以及券配置、发放规则、使用规则、适用范围，原样写入对应工作表。

## 6. 活动核销明细

核销文件先要挂到某一个活动上。

- 这次调用只有一个活动时，全部核销文件都挂到这个活动。
- 有多个活动时，活动配置里的「核销文件」必须是文件名的一段，并且只能命中一个活动。兴路强满减的标记是 `满减-活动明细`，满赠的标记是 `满赠-活动明细`。
- 命中不到，或同时命中多个活动的文件，整份跳过，记入转换报告的 `unbound_execution_files`。
- 「核销文件」只用于配对。它不是标准活动的列，不会写进工作簿。

配对之后，按「活动编号 + 订单号」合并。同一订单在核销文件里有多行时，`促销优惠金额` 相加，`商品总金额` 相加，最后保留两位小数；整数额写成不带小数的文本。

订单号在已写入的订单里找不到时，该行跳过，报告里的 `skipped_execution_orders` 加 1。兴路强试点为 0。客户编号、客户名称、所属业务员优先取订单上已经映射好的值；客户名称在订单上为空时，才用核销行的「客户」。

| 标准活动核销明细 | 来源 |
|---|---|
| 活动编号 | 配对到的活动配置 |
| 活动名称 | 配对到的活动配置 |
| 客户编号 | 订单上的客户编号 |
| 客户 | 订单上的客户名称；订单为空时用核销行「客户」 |
| 所属业务员 | 订单上的业务员 |
| 订单号 | 核销行「订单号」 |
| 商品总金额 | 同一活动、同一订单的「商品总金额」合计 |
| 优惠金额 | 同一活动、同一订单的「促销优惠金额」合计 |

核销行上的「享受促销政策」不写入标准表。

合并完成后，把这些活动编号回写到对应订单每一行的「活动编号」。多个编号用「、」连接，顺序为核销记录出现的顺序，同一编号只写一次。

兴路强试点：满减核销 136 笔，每笔合计优惠 15 元；满赠核销 98 笔。两份核销合计 234 行。

## 8. 履约

每张已写入的订单一行。单据编号是订单号，履约订单状态是该订单第一行保留下来的订单状态。下游订单编号、出库时间、完成时间、结款状态、退货数量留空。

完成时间留空时，后面的释放判断仍看订单状态和下单时间。
