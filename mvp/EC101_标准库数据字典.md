# EC101 标准库数据字典

这份字典说明费用平台正在使用的新库。库文件是 `mvp/ec101_standard.db`，建表语句在 `mvp/ddl/ec101_standard_sqlite.sql`。历史样例库 `mvp/ec101_mvp.db` 的说明仍在 `mvp/EC101_MVP数据库使用说明V1.md`，两份库的表名和字段不能混用。

| 项 | 内容 |
|---|---|
| 数据库 | `mvp/ec101_standard.db`（SQLite） |
| 表数量 | 25 |
| 数据从哪来 | 平台转换器生成的 15 张工作表 `standard.xlsx`，经 `POST /api/imports` 写入 |
| 核算 | 导入成功后立刻运行 `mvp/actual_result_calculator.py`，只统计已经发生的满减、满赠和已使用优惠券 |
| 字典日期 | 2026-10-07。文末行数是当时库里的试点数据，再次导入后会变 |

金额字段在导入时保留两位小数。时间以文本保存，常见形式是 `2026-09-10 16:18:49`；只有日期时是 `2026-09-10`。核算比较时间时，纯日期会补成当天 `00:00:00` 或 `23:59:59`。

## 1. 表怎么分层

| 层 | 表 | 一行代表什么 |
|---|---|---|
| 导入 | `import_batch`、`import_file`、`import_validation_issue` | 一次标准工作簿上传，以及这次上传的归档文件 |
| 主数据 | `dealer_platform`、`customer`、`product` | 一个经销商平台、一名客户、一个商品 |
| 订单 | `order_header`、`order_line`、`fulfillment` | 一张订单、一行商品、一条履约记录 |
| 活动 | `activity`、`activity_rule`、`activity_benefit`、`activity_scope`、`activity_execution` | 一个活动、一条门槛、一项权益、一个适用范围、一笔已核销订单 |
| 优惠券 | `coupon_config`、`coupon_issue_rule`、`coupon_use_rule`、`coupon_scope`、`coupon_redemption` | 一种券的配置、发放规则、使用规则、适用范围、一张券的领用记录 |
| 核算 | `calculation_run`、`entitlement_check`、`release_candidate`、`activity_fee_summary`、`coupon_fee_summary`、`calculation_quality_issue` | 一次核算，以及这笔核算下的发生明细、释放判断、活动汇总、券汇总、质量问题 |

客户、商品、订单、活动和券都带着 `import_batch_id`。同一家经销商再次导入同一平台、同一覆盖区间时，旧批次的 `is_current` 变成 0，新批次变成 1。旧批次的行仍留在库里。`dealer_platform` 按经销商名称加平台名称只保留一行，多家导入共用这一行。

费用页的当前模式只读 `is_current=1` 的批次，并且每个批次只取最新一次 `calculation_run`。

| 标准活动 | `activity` |
| 标准活动规则 | `activity_rule` |
| 标准活动权益 | `activity_benefit` |
| 标准活动范围 | `activity_scope` |
| 标准活动核销明细 | `activity_execution` |
| 标准优惠券配置 | `coupon_config` |
| 标准优惠券发放规则 | `coupon_issue_rule` |
| 标准优惠券使用规则 | `coupon_use_rule` |

## 3. 导入

### import_batch

一次标准工作簿导入。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| import_batch_id | INTEGER | 否 | 主键 |
| snapshot_key | TEXT | 否 | 本次导入的唯一键 |
| dealer_name | TEXT | 否 | 经销商名称，来自导入清单 |
| platform_name | TEXT | 否 | 平台名称，来自导入清单 |
| coverage_start | TEXT | 可 | 数据开始日期 |
| coverage_end | TEXT | 可 | 数据结束日期 |
| template_version | TEXT | 否 | 标准模板版本 |
| converter_version | TEXT | 否 | 转换工具版本 |
| imported_at | TEXT | 否 | 导入时间 |
| status | TEXT | 否 | 导入过程中为 `importing`，核算完成后为 `calculated` |
| is_current | INTEGER | 否 | `1` 表示这一经销商、平台、覆盖区间的当前批次；`0` 表示已被同范围的新导入替换 |

同一 `dealer_name + platform_name + coverage_start + coverage_end` 再导入时，旧行的 `is_current` 改为 0。覆盖日期都为空时，空值也参与这个匹配。

### import_file

这次导入附带的归档文件。当前每批一行，`file_role` 为 `sources`。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| import_file_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| file_role | TEXT | 否 | 文件角色。当前为 `sources` |
| file_path | TEXT | 否 | 归档文件在本机的路径 |
| sha256 | TEXT | 否 | 文件内容的 SHA-256 |
| file_size | INTEGER | 否 | 文件字节数 |

### import_validation_issue

预留给导入校验问题的表。当前导入若校验失败，接口直接返回错误，不往这张表插行。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| issue_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 可 | 所属导入批次 |
| code | TEXT | 否 | 问题代码，如缺少客户、缺少订单 |
| sheet_name | TEXT | 可 | 工作表名 |
| row_number | INTEGER | 可 | 工作表行号 |
| column_name | TEXT | 可 | 字段名 |
| message | TEXT | 否 | 问题说明 |

## 4. 主数据

### dealer_platform

一个经销商在一个平台上的身份。快马兴路强、舟谱羿柏各一行。客户、商品、订单通过 `dealer_platform_id` 指向这里。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| dealer_platform_id | INTEGER | 否 | 主键 |
| dealer_name | TEXT | 否 | 经销商名称。与 `platform_name` 联合唯一 |
| platform_name | TEXT | 否 | 平台名称 |

### customer

一个导入批次里的一名客户。同一批次内 `customer_no` 唯一。客户编号只在本批次内查找，不跨批次合并。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| customer_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| dealer_platform_id | INTEGER | 否 | 经销商平台 |
| customer_no | TEXT | 否 | 客户编号 |
| customer_name | TEXT | 否 | 客户名称 |
| customer_type | TEXT | 可 | 客户类型 |
| customer_region | TEXT | 可 | 客户区域 |
| address | TEXT | 可 | 详细地址 |
| phone | TEXT | 可 | 联系电话 |
| added_at | TEXT | 可 | 添加时间 |
| salesperson | TEXT | 可 | 所属业务员 |

订单里出现、主数据里没有的客户，转换器会补一行，名称用来源行上的客户名称。舟谱未能解析的客户，编号以 `UNRESOLVED:` 开头。

### product

一个导入批次里的一个商品。同一批次内 `product_no` 唯一。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| product_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| dealer_platform_id | INTEGER | 否 | 经销商平台 |
| product_no | TEXT | 否 | 商品编号 |
| product_name | TEXT | 否 | 商品名称 |
| brand | TEXT | 可 | 品牌 |
| category | TEXT | 可 | 商品目录 |
| barcode | TEXT | 可 | 商品条码 |
| spec | TEXT | 可 | 规格 |
| base_unit | TEXT | 可 | 基本单位 |
| box_conversion | TEXT | 可 | 箱规，原文保留 |
| base_qty_per_box | NUMERIC | 可 | 每箱基本单位数量 |

订单里出现、主数据里没有的商品，转换器会按订单行补一行。舟谱对不上主数据的商品，编号以 `UNMATCHED:` 开头，名称仍保留平台原文。

## 5. 订单与履约

### order_header

一张业务订单。同一批次内 `order_no` 唯一。订单明细里同一个单据编号的多行，合成这一张订单头，行上的客户、状态、下单时间取第一次写入的那一行。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| order_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| dealer_platform_id | INTEGER | 否 | 经销商平台 |
| order_no | TEXT | 否 | 单据编号 |
| order_time | TEXT | 可 | 下单时间。释放判断用这个时间，不用履约完成时间 |
| customer_no | TEXT | 否 | 客户编号 |
| customer_name | TEXT | 可 | 客户名称 |
| salesperson | TEXT | 可 | 业务员 |
| order_source | TEXT | 可 | 订单来源。舟谱里可见 `XD履约(无SXD)` |
| order_type | TEXT | 可 | 订单类型 |
| order_status | TEXT | 否 | 订单状态。可释放要求这个值等于 `已完成` |
| payment_method | TEXT | 可 | 支付方式。释放判断不看支付方式 |
| downstream_order_no | TEXT | 可 | 下游订单编号。舟谱用于记录 SXD 对应的 XD |

当前库里出现过的订单状态：`已完成`、`已下发`、`待签收`、`待收货`、`待出库`、`部分发货`、`待发货`、`待审核`、`未下发`、`待发货[取消中...]`。

### order_line

订单上的一行商品。一张订单可以有多行，没有“一单一行”的唯一约束。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| order_line_id | INTEGER | 否 | 主键 |
| order_id | INTEGER | 否 | 所属订单 |
| product_no | TEXT | 否 | 商品编号 |
| product_name | TEXT | 可 | 商品名称。满赠在没有核销明细时，用这个名称或商品主数据名称匹配赠品 |
| category | TEXT | 可 | 商品目录 |
| spec | TEXT | 可 | 规格 |
| barcode | TEXT | 可 | 商品条码 |
| unit | TEXT | 可 | 单位 |
| quantity | NUMERIC | 可 | 数量。赠品实发按这个数量合计 |
| pre_discount_amount | NUMERIC | 可 | 优惠前金额 |
| activity_numbers | TEXT | 可 | 这一行带上的活动编号。同一订单参加多个活动时，编号用顿号连在一起 |
| coupon_numbers | TEXT | 可 | 这一行带上的优惠券编号 |
| discount_amount | NUMERIC | 可 | 这一行的优惠金额。它是平台订单行上的优惠，活动核算不把各行这个字段加总当成满减 |
| paid_amount | NUMERIC | 可 | 实付金额 |
| unit_price | NUMERIC | 可 | 单价 |
| return_qty | NUMERIC | 可 | 退货数量 |

### fulfillment

一条履约记录，按导入批次和单据编号保存。它不强制指向 `order_header`。核算器把它当作证据，释放判断看的是订单头的状态和下单时间；`completed_at` 为空时，不因此拒绝释放。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| fulfillment_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| order_no | TEXT | 否 | 单据编号 |
| downstream_order_no | TEXT | 可 | 下游订单编号 |
| fulfillment_status | TEXT | 否 | 履约订单状态 |
| outbound_at | TEXT | 可 | 出库时间 |
| completed_at | TEXT | 可 | 完成时间 |
| settlement_status | TEXT | 可 | 结款状态 |
| return_qty | NUMERIC | 可 | 退货数量 |

## 6. 活动

### activity

一个促销活动。同一批次内 `activity_no` 唯一。实际发生核算不重算门槛，但会读取活动类型、促销方式、开始和结束时间：类型或促销方式里带“赠”，并且权益类型是赠品时，按赠品数量统计。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| activity_no | TEXT | 否 | 活动编号 |
| activity_name | TEXT | 否 | 活动名称 |
| activity_type | TEXT | 否 | 活动类型，如 `满减`、`满赠` |
| promo_method | TEXT | 可 | 促销方式，如 `满一定金额立减`、`满一定金额立赠` |
| start_time | TEXT | 否 | 开始时间。没有核销明细的满赠，用它圈定赠品行 |
| end_time | TEXT | 否 | 结束时间 |
| allow_activity_stack | TEXT | 可 | 是否允许叠加活动 |
| allow_coupon_stack | TEXT | 可 | 是否允许叠加优惠券 |
| activity_status | TEXT | 否 | 活动状态，如 `已结束` |

### activity_rule

活动的一条门槛。同一活动内 `rule_no` 唯一。实际发生核算不使用门槛值和立减金额来重算理论优惠。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_rule_id | INTEGER | 否 | 主键 |
| activity_id | INTEGER | 否 | 所属活动 |
| rule_no | TEXT | 否 | 规则编号 |
| threshold_type | TEXT | 否 | 门槛类型，如 `金额` |
| threshold_value | NUMERIC | 可 | 门槛值 |
| reduce_amount | NUMERIC | 可 | 立减金额 |
| free_shipping | INTEGER | 可 | 是否免邮。`1` 表示是，默认 `0` |

### activity_benefit

活动的一项权益。同一活动内 `rule_no + benefit_no` 唯一。`benefit_type='赠品'` 时，核算器用赠品编号或赠品名称去数订单行。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_benefit_id | INTEGER | 否 | 主键 |
| activity_id | INTEGER | 否 | 所属活动 |
| rule_no | TEXT | 否 | 规则编号 |
| benefit_no | TEXT | 否 | 权益编号 |
| benefit_type | TEXT | 否 | 权益类型。赠品必须写成 `赠品` |
| gift_product_no | TEXT | 可 | 赠品商品编号。有编号时按编号匹配，名称为空也能数到 |
| gift_product_name | TEXT | 可 | 赠品商品名称。匹配订单行名称，也匹配同编号商品主数据的名称 |
| gift_qty | NUMERIC | 可 | 配置上的每次赠品数量。实发数量不取这个字段，取订单行数量 |
| gift_unit | TEXT | 可 | 赠品单位 |

### activity_scope

活动的一个适用范围。实际发生核算不按范围再过滤订单。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_scope_id | INTEGER | 否 | 主键 |
| activity_id | INTEGER | 否 | 所属活动 |
| scope_no | TEXT | 否 | 范围编号 |
| scope_category | TEXT | 否 | 范围类别，如 `商品`、`客户`、`限购` |
| scope_dimension | TEXT | 否 | 范围维度，如 `商品编号`、`品牌`、`客户类型`、`商品名称前缀` |
| scope_value | TEXT | 否 | 范围值 |

### activity_execution

一个活动在一张订单上的核销。同一活动、同一订单只有一行；转换器把平台活动明细按订单汇总优惠金额后再写入。

有核销行时，这些订单就是参加活动的订单。满减把 `discount_amount` 加总。满赠只在这些订单上数赠品行，订单行上的优惠金额不另算一笔满减。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_execution_id | INTEGER | 否 | 主键 |
| activity_id | INTEGER | 否 | 所属活动 |
| order_id | INTEGER | 否 | 核销订单。订单必须已经在本批次的订单头里 |
| activity_name | TEXT | 可 | 活动名称 |
| customer_no | TEXT | 可 | 客户编号 |
| customer_name | TEXT | 可 | 客户 |
| salesperson | TEXT | 可 | 所属业务员 |
| product_amount | NUMERIC | 可 | 该订单在活动明细里的商品总金额 |
| discount_amount | NUMERIC | 可 | 该订单在活动明细里的优惠金额合计 |

## 7. 优惠券

活动和优惠券分成两套表。券通过 `coupon_redemption.order_id` 连到订单，不连到 `activity`。

### coupon_config

一种优惠券配置。同一批次内 `config_no` 唯一。一个批次只有一种配置时，该批次全部已使用券都归到这一种。多种配置时，用券名称是否包含在券编号里来归属；对不上的券单独汇总，`coupon_config_id` 为空。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_config_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| config_no | TEXT | 否 | 优惠券配置编号 |
| coupon_name | TEXT | 否 | 优惠券名称 |
| coupon_type | TEXT | 可 | 券类型 |
| config_status | TEXT | 否 | 配置状态 |

### coupon_issue_rule

一种券的发放规则。一种配置最多一行。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_issue_rule_id | INTEGER | 否 | 主键 |
| coupon_config_id | INTEGER | 否 | 所属券配置，唯一 |
| issue_mode | TEXT | 否 | 发放方式 |
| issue_start_at | TEXT | 否 | 发放开始时间 |
| issue_end_at | TEXT | 可 | 发放结束时间 |
| auto_issue_at | TEXT | 可 | 自动发放时间 |
| qty_per_issue | NUMERIC | 否 | 每次发放数量 |
| max_claim_per_customer | NUMERIC | 可 | 每客户领取上限 |
| daily_claim_limit | NUMERIC | 可 | 每日领取上限 |
| rule_status | TEXT | 否 | 规则状态 |

### coupon_use_rule

一种券的使用规则。一种配置最多一行。实际发生核算不按这里的门槛重算券金额，金额取核销明细上的优惠金额。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_use_rule_id | INTEGER | 否 | 主键 |
| coupon_config_id | INTEGER | 否 | 所属券配置，唯一 |
| coupon_type | TEXT | 否 | 券类型 |
| validity_mode | TEXT | 否 | 有效期类型 |
| use_start_at | TEXT | 可 | 使用开始时间 |
| use_end_at | TEXT | 可 | 使用结束时间 |
| valid_days_after_receive | INTEGER | 可 | 领取后有效天数 |
| max_use_per_coupon | NUMERIC | 否 | 每张券最多使用次数 |
| rule_status | TEXT | 否 | 规则状态 |

### coupon_scope

一种券的一个适用范围。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_scope_id | INTEGER | 否 | 主键 |
| coupon_config_id | INTEGER | 否 | 所属券配置 |
| scope_no | TEXT | 否 | 范围编号 |
| scope_category | TEXT | 否 | 范围类别 |
| scope_dimension | TEXT | 否 | 范围维度 |
| scope_value | TEXT | 否 | 范围值 |

### coupon_redemption

一张券的领用或使用记录。核算只取 `status='已使用'` 的行。`已领取` 不计入金额。`order_id` 可以为空：券发生了，但没有唯一订单，不能释放。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_redemption_id | INTEGER | 否 | 主键 |
| import_batch_id | INTEGER | 否 | 所属导入批次 |
| order_id | INTEGER | 可 | 使用这张券的订单。单号对不上，或一张券写了多个订单号时为空 |
| coupon_no | TEXT | 否 | 优惠券编号 |
| customer_no | TEXT | 否 | 领取客户编号 |
| customer_name | TEXT | 可 | 领取客户 |

## 8. 核算结果

一次导入产生一次 `calculation_run`。下面五张结果表都挂在这次核算上。费用页若指定 `calc_batch_id`，这个值就是 `calculation_run_id`。

可释放的统一条件：订单状态为 `已完成`，且下单时间早于或等于核算日减 2 天的零点。例如核算日 `2026-09-23`，截止时间是 `2026-09-21 00:00:00`。没有订单的券不能释放。履约完成时间为空不否决。

### calculation_run

一个导入批次的一次核算。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| calculation_run_id | INTEGER | 否 | 主键。费用接口里的 `calcBatchId` |
| import_batch_id | INTEGER | 否 | 被核算的导入批次 |
| calc_date | TEXT | 可 | 核算日。命令行导入可指定；费用平台页面上传时取上传当天 |
| activity_benefit | NUMERIC | 否 | 满减等金额活动的实际优惠合计。赠品活动不计入 |
| coupon_benefit | NUMERIC | 否 | 已使用券的优惠合计，包含没挂上订单的券 |
| total_benefit | NUMERIC | 否 | `activity_benefit + coupon_benefit` |
| status | TEXT | 否 | 当前为 `calculated` |

### entitlement_check

一笔已经发生的活动权益，粒度是“一次核算、一张订单、一个活动”。赠品行的金额记 0，数量记在 `gift_qty_actual`。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| entitlement_check_id | INTEGER | 否 | 主键 |
| calculation_run_id | INTEGER | 否 | 所属核算 |
| order_id | INTEGER | 可 | 订单 |
| activity_id | INTEGER | 可 | 活动 |
| activity_benefit | NUMERIC | 可 | 该订单该活动的金额优惠。赠品为 0 |
| coupon_benefit | NUMERIC | 可 | 这张明细上的券优惠。活动明细里当前写 0，券另走券汇总 |
| total_benefit | NUMERIC | 可 | 该行金额合计 |
| gift_qty_entitled | NUMERIC | 可 | 应赠数量。实际发生核算不写应赠，当前为空白 |
| gift_qty_actual | NUMERIC | 可 | 实发赠品数量 |
| consistency | TEXT | 可 | 实际发生核算固定写 `已发生` |

### release_candidate

一张参加了活动或挂上了已使用券的订单，是否到达可释放节点。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| release_candidate_id | INTEGER | 否 | 主键 |
| calculation_run_id | INTEGER | 否 | 所属核算 |
| order_id | INTEGER | 否 | 订单 |
| is_candidate | INTEGER | 否 | `1` 可释放，`0` 不可释放 |
| reason | TEXT | 可 | `已完成且下单时间≤核算日减2天`，或 `订单未完成或下单时间晚于核算日减2天` |

### activity_fee_summary

一个活动在一次核算中的汇总。赠品活动的金额为 0，数量单独列出，结算状态为 `按赠品数量统计(不结算单价)`。金额活动的结算状态为 `金额优惠`。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| activity_fee_summary_id | INTEGER | 否 | 主键 |
| calculation_run_id | INTEGER | 否 | 所属核算 |
| activity_id | INTEGER | 否 | 活动 |
| actual_discount_total | NUMERIC | 否 | 实际优惠金额。赠品活动为 0 |
| gift_cost_total | NUMERIC | 否 | 赠品成本。单价未确认时为 0 |
| gift_qty_entitled | NUMERIC | 可 | 应赠数量。实际发生核算留空 |
| gift_qty_actual | NUMERIC | 可 | 实发赠品数量 |
| releasable_discount_total | NUMERIC | 可 | 可释放金额 |
| releasable_gift_qty | NUMERIC | 可 | 可释放赠品数量 |
| release_order_count | INTEGER | 可 | 可释放订单笔数 |
| settle_status | TEXT | 可 | `金额优惠` 或 `按赠品数量统计(不结算单价)` |

### coupon_fee_summary

一种券在一次核算中的汇总。只统计状态为已使用的券。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| coupon_fee_summary_id | INTEGER | 否 | 主键 |
| calculation_run_id | INTEGER | 否 | 所属核算 |
| coupon_config_id | INTEGER | 可 | 券配置。没能归到某一种配置时为空 |
| used_count | INTEGER | 否 | 已使用张数 |
| used_amount | NUMERIC | 否 | 已使用金额，含未挂上订单的券 |
| linked_amount | NUMERIC | 否 | 已挂上唯一订单的金额 |
| releasable_count | INTEGER | 否 | 可释放张数 |
| releasable_amount | NUMERIC | 否 | 可释放金额 |
| unlinked_count | INTEGER | 否 | 未挂上唯一订单的张数 |
| unlinked_amount | NUMERIC | 否 | 未挂上唯一订单的金额。这部分算发生了，不能释放 |
| settle_status | TEXT | 可 | 当前为 `金额优惠` |

费用页把券显示成金额活动。展示用的活动编号是券配置编号的相反数；配置为空时用 `-1`。

### calculation_quality_issue

一次核算发现的质量问题。当前问题不挂到单个活动编号上，费用页里的 `activityId` 为空。

| 字段 | 类型 | 空 | 说明 |
|---|---|---|---|
| calculation_quality_issue_id | INTEGER | 否 | 主键 |
| calculation_run_id | INTEGER | 否 | 所属核算 |
| order_no | TEXT | 可 | 相关订单号。批次级问题为空 |
| issue_type | TEXT | 否 | 问题类型 |
| level | TEXT | 否 | `警告` 或 `提示` |
| reason | TEXT | 否 | 问题说明，含张数和金额 |

当前核算器会写的类型：

| issue_type | level | 什么时候出现 |
|---|---|---|
| 核销订单没有赠品行 | 警告 | 满赠核销订单上没有匹配的赠品行 |
| 赠品权益缺少赠品 | 警告 | 活动被识别为赠品，但没有赠品编号或名称 |
| 返券双单号无法唯一归因 | 警告 | 已使用券关联了多个订单号 |
| 返券单号未命中订单 | 警告 | 已使用券没有唯一订单 |
| 券领取客户未匹配 | 警告 | 券上的客户编号在本批次客户表里不存在 |
| T-2释放口径 | 提示 | 每次核算都写一条，说明可释放条件 |
